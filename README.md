# local-rag-service-demo

> 本地知识库问答（RAG）最小完整实现：**护栏 → 混合检索 → 受控生成** 三层架构，附带锚点法评测基线。
> 纯 Python 标准库实现，零第三方依赖；模型与向量服务全部本地运行（Ollama），数据不出机器。

## 项目概述

把 6 份家电售后知识库文档（按条款切成 32 个知识块）变成可问答的本地服务。语料为虚构脱敏数据，业务逻辑参照真实售后履约场景（保修政策、收费与赔付、服务时效、投诉处理）。

项目定位是**产品视角的技术验证**：验证的不是模型能力上限，而是——

1. 一条完整 RAG 链路在生产化之前会在哪里失败（失败模式清单）
2. 每类失败应该在哪一层解决（护栏 / 检索 / 生成 / 模型选型）
3. 怎样用可复现的评测把"感觉变好了"变成"通过率从 X 到 Y"

## 架构

```
用户问题
   ↓
① 护栏层   红线规则（隐私/越权、竞品比价）关键词组合前置拦截，
           命中直接固定话术拒答——不检索、不调模型（0.0s）
   ↓
② 检索层   bge-m3 向量化 → 与 32 个知识块算余弦相似度 → 取 top5
           （同文档最多 2 块，防单一来源）＋ 品类/主题关键词过滤（防邻位污染）
   ↓        最高分 < 0.45 视为知识库无依据 → 直接拒答，不硬答
③ 生成层   qwen2.5:7b（temperature 0.2），只依据 top5 回答，
           强制标注引用编号 [n]，输出带溯源
   ↓
回答 + 溯源（本条答案依据了哪几份文档）
```

**混合检索的动机**：向量衡量"像不像"，关键词校验"是不是"。实测中，删除知识库一条保修条款后，模型没有拒答，而是把同块内其他品类的条款张冠李戴——纯向量检索防不住这类"邻位污染"，必须叠一层实体过滤。

## 快速开始

环境要求：

- [Ollama](https://ollama.com)，已拉取 `qwen2.5:7b` 与 `bge-m3`
- Python 3.9+（无需安装任何包）

```bash
git clone https://github.com/Charles0538/local-rag-service-demo.git
cd local-rag-service-demo

# 单次问答（--debug 可查看每个候选块的相似度分数）
python3 04_rag.py "空调显示 E5 是什么故障，需要报修吗？"

# 跑评测基线（10 条，锚点法二值判定 + 记录每条走哪一层）
python3 05_eval.py

# 单题复跑（稳定性验证）
python3 05_eval.py Q003

# 稳定性实验：同一题连跑 N 次（概率性失败量化）
python3 06_experiment.py Q003                # 默认 prompt，temperature 0.2，11 次
python3 06_experiment.py Q003 --temp 0       # temperature 0：确定性但未必正确
python3 06_experiment.py Q003 --strict       # 结构化抽取 + 生成后校验模式

# 问答主程序也支持 --strict（金额/时限由代码保证，生成后校验缺了重试一次）
python3 04_rag.py --strict "师傅爽约了怎么投诉"
```

首次运行会自动构建向量索引并缓存（约 2.3s / 32 块），文档更新后自动重建。

## 评测基线

评测集 10 条：常见问题 6 / 长尾 2 / 对抗 2，含红线标注。

**判定方法：关键事实锚点法（二值法）**——每题预置 1–3 组锚点，锚点全部来自知识库原文硬事实（金额 / 时限 / 年限 / 关键动作），全部命中 = PASS。不使用 LLM 打分，保证基线可复现、零成本、可解释。同时记录每条走的层（护栏 / 拒答 / 生成），红线题要求"该走护栏的必须走护栏"——这是成本与安全的双重验收。

**基线结果（qwen2.5:7b + bge-m3，MIN_SCORE=0.45）**：

| 指标 | 数值 |
|---|---|
| 单次全量通过 | **9/10** |
| 红线护栏拦截 | 2/2（0.0s，未调用模型） |
| 生成层平均耗时 | 7.1s |
| 不稳定 case 连跑 5 次通过率 | 3/5 |

基线存档于 `eval_results.json`，作为后续换模型 / 调参数的对照基准。

## 关键实测发现

1. **检索分高 ≠ 有依据。** 问「冰箱保修十年是真的吗」，最高分 0.68（语义高度相关）但知识库并无此条。分数只说明"像"，不说明"有"——分数门槛（0.45，依据相关/无关问题的分数分布实测校准）与实体过滤缺一不可。
2. **7B 对否定式规则的执行率很低。** 「涉及他人隐私一律拒绝」「不做竞品比价」写进 prompt，实测模型会顺着资料答。改法：红线不交给模型判断，代码层前置拦截。这也印证了企业里「规则引擎 + LLM」分层的必要性。
3. **邻位污染是最隐蔽的失败模式。** 删除一条知识后，模型用同块内其他品类的条款填空（张冠李戴）；过滤收紧后，又退化为用常识填空。修法 = 混合检索：品类词与主题词双命中才保留，全滤光则触发拒答。
4. **prompt 规则的执行是概率性的，温度 0 也救不了。** 同一条"资料中含赔付条款必须写出"的规则，连跑结果随机（详见稳定性实验一节：3/11 → 8/11 跨天漂移）；temperature 0 把输出冻成一字不差，但冻住的答案照样漏关键数值。结论：关键内容不能依赖 prompt 兜底——结构化抽取（代码抽数值拼「必须包含清单」）+ 生成后校验（缺了重试一次）才能到 11/11，代价是约 3 倍延迟。
5. **评测能抓到"业务上会翻车"的单次对话错。** 基线唯一失败项：答案「保修期内上门维修不收费」单次对话不算错，但省略了「人为损坏收 50 元检测费」的例外条款——生产环境即客诉。
6. **同一份文档会挤占 top-k。** top5 中 4 块同源导致答案视角单一，加"同文档最多 2 块"约束后恢复正常。

## 设计决策

**为什么选 7B 而不是更大的模型**：14B Q4 约 9GB，在 24GB 统一内存设备上与系统/浏览器争抢内存，换页后速度腰斩（8–10 token/s）；且换模型只对"生成不稳定/指令遵循弱"两类错误有效，对知识缺失、召回错误、邻位污染无效。原则：**先有评测基线，再谈换模型**——用同一份评测集跑分数差来证明值不值，而不是拍脑袋。

**为什么按标题切分而不是固定长度滑窗**：政策文档的原子语义单元是条款；固定字数会把并列条款拦腰截断（"空调 3 年/冰箱 1 年/洗衣机 3 年"只剩半条），且标题即元信息、引用可人工核对。滑窗重叠防的是"答案跨切割点"，标题切分的边界即语义边界，无需重叠。

**为什么红线走代码不走 prompt**：红线回复必须确定、可审计、零成本。固定话术 + 前置拦截（1 秒内、不调模型）在安全与成本上都优于让模型自行判断。

## 稳定性实验（2026-11-28 补测）

针对发现 4 的量化实验：固定 Q003「师傅爽约了怎么投诉」（知识库明确写着赔付标准：50 元服务券、24 小时改派），检索每次都正确命中，波动只发生在生成层。同一把锚点尺子，连跑 11 次：

| 方案 | 结果 | 平均耗时 | 说明 |
|---|---|---|---|
| 默认 prompt，temperature 0.2 | **3/11** | 4.6s | 同一配置在 11-24 实测为 8/11——通过率本身跨天漂移 |
| 默认 prompt，temperature 0 | **0/11** | 4.5s | 11 轮输出一字不差：确定性 ≠ 正确性，它只是把"最可能的答案"冻住，而最可能的答案恰好漏了赔付金额 |
| 结构化抽取 + 生成后校验（`--strict`） | **11/11** | 13.0s | 3 轮首次生成漏数值，靠生成后校验兜住重试；代价 = 约 3 倍延迟 |

**门槛压力测试**：把 MIN_SCORE 抬到 0.78（压进正常题 0.72–0.77 的分数区间内部），全量回归通过 2/10——8 条正常题全部被误杀为"未收录"，生成层 0 次调用。0.45 / 0.60 / 0.78 三个门槛的实测对照见仓库文章。

结论：**prompt 只能提高概率，保证不了行为；温度 0 换来的是确定性不是正确性；要保证行为，把数字从模型手里拿走（代码抽取）再用代码验收（生成后校验）——并且要为这份保证付 3 倍延迟的账。**

## 已知局限

- 切块按标题切，不识别语义边界；表格与跨小节引用会断
- 无 rerank，top5 仍含噪声块
- 关键词护栏是窄规则，覆盖不了改写问法（须靠评测集持续补充对抗样本）
- 7B 在 5 块约 3000 字上下文时已有注意力衰减，会漏条款
- 单轮问答，无会话记忆与工具调用
