## 一句话记法

- **两条永远对**：Q004 老王订单、Q009 比价——因为是代码拦截，不是模型。
- **两条看运气**：Q001 收费、Q003 爽约——都是「要写出具体金额」的题，模型抽签。

## 面试追问四连（2026-11-28 用户提问，标准答案）

**Q：为什么跑 11 遍？**
11 没有统计依据，跑 10 遍也行。逻辑：跑 1 遍只能知道"这次对错"，跑 N 遍才知道"稳定还是看运气"；当时唯一待答问题是"它是不是 100% 可靠"，错 3 次即有答案。约束：一遍 5 秒，11 遍一分钟。要点不是 11 这个数，是**固定 N、所有对比用同一把尺**。局限：11 次估不出精确通过率，给的是机制证据；生产要几百上千次，且盯趋势比盯精确数字更有意义（跨天漂移实证）。

**Q：随机性是哪个参数？调它有什么后果？**
temperature（温度），生成调用里的 options 参数，当前 0.2。模型每写一个字从"候选词概率表"抽签，温度=冒险程度：趋近 0 → 几乎总抽最高概率词，可复现；调高 → 低概率词也可能被抽中，发散。后果两面：调低=可复现，但只是把"最常见的答案"冻住——最常见的答案本身漏 50 元，它就稳定地错（11-28 实测 temp0=0/11 一字不差）；调高=适合发散场景但问答飘。**温度治"不稳定"，不治"错误"**。

**Q：加保险具体怎么落实？分哪些层？**
三步全在代码层，模型只负责组织语言：①抽取（检索后、生成前）：extract_facts() 正则从最高分知识块抠硬数值（元/小时/年）——爽约块抽出 50 元/100 元/2 小时/24 小时；只取最高分块，避免无关数值混入。②注入（生成输入侧）：清单拼进 prompt"凡涉及相关内容必须原样写出"（不是"全部写进答案"）。③校验+重试（生成输出侧）：verify_facts() 检查答案是否含清单数值，缺了追加提示重发一次（11 轮里 3 轮靠它兜回）。本质：概率问题 → 确定性流程。

**Q：这套方案能普遍应用吗？**
本质="机器管事实，模型管表达"。适用：验收标准可机械抽取的场景（金额/时限/日期/单号/条款编号）。前提：知识块半结构化 + **召回必须先正确**（召回错块→清单错→保险失灵，它是建立在混合检索之上的，不是替代）。不适用：主观维度（要 LLM-as-judge）、跨块综合题（例外条款在另一块，只抽最高分块会漏）。成本：重试=双倍耗时，哪些字段值得花钱保证=产品经理的验收标准决策（50 元赔付值得，礼貌用语不值得）。

**Q：护栏枚举拦不完所有人名（张三李四王五枚举不完），那规则层还有什么意义？（2026-11-28 追问五）**
先承认：枚举不可行，纯规则做红线卡控确实有天花板——这正是生产护栏要**分层**的根本原因。四层阶梯从便宜到贵：
1. **规则层只拦结构信号，不拦实体**：人名无限，但"查询动作+订单+第三方指向"的结构稳定；规则=快筛不是终审；
2. **小模型分类器**：毫秒级零成本做意图识别，"是不是在查他人信息"——开放集合问题在这层被接住（它懂意图，不懂具体人名）；
3. **LLM 兜底**：只接前两层漏下的极小流量；漏斗结构（规则 0 成本→分类器毫秒→LLM 秒级），整体成本才压得住；
4. **最彻底：权限根除**：不是识别"他在查别人的订单"，而是让"按任意名字查单"的能力不存在——查单工具只接受当前登录态用户参数，不接受任意姓名。**规则和分类器是在猜坏人的问法，权限设计是直接没收作案工具**。防护的终点不在识别，在授权——这层是产品经理的主场（工具参数暴露、默认权限、异常降级）。
demo 的诚实做法：承认局限是实验产出之一；对抗样本持续喂（漏一次补一条）；文档明说"此层只挡第一波"。一句话：**规则层的意义不是拦住一切，而是零成本消化大部分+给下层争取流量**——防线是梯子，不是一堵墙。
